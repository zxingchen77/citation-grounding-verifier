2026 年 11 月 2 日评审基于 `e04959a0091561df87ef09433c37c7dc53bb5189`，得分 85 / 100。现有版本已满足[作业](https://gist.github.com/wsxiaoys/849522ee389e0ce359ef444653084484)的硬性要求。本轮修改重点是提高评测的区分度、确认优化方案的收益，并补足真实模型接口的验收证据。

## 已确认的基础

39 项测试、lint 和格式检查通过。40 条确定性基线可以运行；保存的开发集与测试集结果可以完整重算，源码和数据哈希一致。引用索引、原文子串、标签与引用关系由代码校验，错误不会被静默降级为 UNSUPPORTED。

原始 40 个案例属于 20 个场景家族，每例上下文合计 97–201 个字符，每个答案内的声明标签相同。原测试集 minimal F1 为 1.000，optimized 为 0.964；optimized 输出 token 更少，但总 token 略增，单次运行不能证明稳定提速。

## 优先级一 扩充有区分度的数据

新增独立的 `challenge-v1` 数据及清单，保留原始数据、历史结果和哈希。至少 24 个新案例，12 个开发案例、12 个测试案例，按场景家族隔离；不要仅替换原案例的名称或数字。

- 至少 18 个案例在一个答案中混合两种以上标签，其中至少 6 个包含全部三种标签。
- 覆盖条件与例外、范围和否定、精确配置与纯上下界、非排他的事实、同义改写与指代、多段证据和相关但不足的干扰信息。每个测试切片都应有开发侧的能力覆盖，但不能复用同一场景。
- 上下文应有自然的多句段落，多数案例合计约 500–2000 个字符、答案包含 3–6 个原子声明。长度用于检查复杂度，不通过无关填充满足数字。
- 每个标签提供简短标注理由；支持或矛盾声明给出足够的证据组。涉及数字、权限、端口等情况，明确区分“唯一配置”“仅给出一个事实”“逻辑上界”。
- 数据冻结前由审核会话逐条复核标签、声明拆分及证据。准确标记为另一个 AI 会话复核，不能称独立人工标注。

验收：数据结构与引用检查通过；类别、标签组合、长度、声明数量和家族划分可自动统计；测试数据在最终推理前冻结并记录哈希。

## 优先级二 让实验足以支持方案选择

保留 deterministic、minimal、optimized 三种必需方法；staged 可继续作为历史备选，不因本轮任务增加无证据的系统复杂度。

- runner 支持可复现的交替或平衡方法顺序，记录实际执行顺序与随机种子；同一案例同一轮次的结果可以配对比较。
- 在新开发集比较三个方法，只有观察到问题时才修改 prompt 或实现。记录失败、修改理由和前后结果；将数据修订与模型改进分开。
- 选定实现和评测规则后，由审核会话检查冻结材料，随后才运行新测试集。两种 LLM 方法至少各重复 3 次；确定性方法运行一次即可。
- 报告每轮及汇总的端到端 F1、原始 TP/FP/FN、声明覆盖、引用有效性、证据充分性、错误数、延迟、输入和输出 token、缓存和模型调用数。不要把同一案例的重复运行当作新的独立案例。
- 可用按案例或家族聚类的配对 bootstrap 描述质量差异的不确定性，并披露小样本限制；延迟结论只限于所用后端及执行条件。
- 如 optimized 没有稳定收益，明确说明取舍和实际推荐方法。完成作业不要求强行宣称 optimized 获胜，也不保证修改后必得 90 分。

验收：原始预测与 traces 保留，汇总能够重算；失效请求和修复调用纳入统计；测试输出不再用于本轮 prompt 选择或修改标签提高得分。

## 优先级三 补足接口与错误边界验证

对现有 HTTPModel 的严格结构化请求、成功响应、畸形返回、上游错误、超时和有限修复做有实际意义的检查，修复发现的缺陷。避免只为增加测试数量而编写重复断言。

如果本机已有可用且获授权的 HTTP 模型配置，执行真实 HTTP 模型验收并记录脱敏后的请求参数、响应、模型标识、时间和用量；不得读取或输出凭据。如果只有现有 Codex 登录，则完成该后端的真实服务验收，并将“直接 HTTP 模型调用尚未验证”列为明确缺口，不冒充已通过、不申请或购买新服务。

## 交付与审核流程

实施会话在现有本地 checkout 工作，完成代码、挑战数据、文档和相关测试。先交付可审核的实现及数据，不运行新的测试集模型推理。审核会话检查 diff、标注、评分和冻结材料后，再通知实施会话运行最终实验。

最终审核需要：

1. 复查新增代码与数据，验证引用和错误处理不回归。
2. 运行 lint、格式检查和测试；执行真实本地 HTTP 冒烟检查。
3. 重算新实验结果，核对冻结哈希、实际方法顺序和原始调用记录。
4. 核对 README 中每个新增结论，明确剩余缺口，并按原评分维度复评。

允许为冻结和审阅创建本地提交。完成审核前不推送远端或发布。实施会话负责修正审核发现的问题；审核会话负责最终验收。
